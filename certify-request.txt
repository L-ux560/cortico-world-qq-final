package: cortico-world-qq-final
reason: Third-party QQ (OneBot v11 / NapCat / SnowLuma) world adapter maintained by hth768. Re-applying for certification after the 0.3.x review (issue #104) and many follow-up releases up to 0.6.19. Re-confirming the four certification requirements and the five review points from #104; all are still met, several strengthened.
(0) No basic problems - `pnpm check:extension` passes with zero failures: manifest kind=world/api=6, entry src/index.ts, world id=qqbot, browser bundle + style present, 14 panels, 3 config groups, 13 tools, 8 events, 1 prompt, every tool declared in describe.json (regenerated and matches code), CHANGELOG has a "## 0.6.19" section, declared tags im/qq/external-setup all valid against the vocabulary (maintainers additionally applied the unofficial-api tag because the adapter logs into QQ via SnowLuma/NapCat).
(1) Stable in real use - runs on a live Coopanion deployment (Node 22), installed from the market, connects to an OneBot v11 reverse WebSocket endpoint (SnowLuma; previously tested with NapCat), receives and sends group/private messages; three console status lamps report connection / identity / guard state. (Correction from #104: my earlier "v0.3.3" was a misread of a screenshot; the real deployed build at that time was resources/app/package.json = 0.2.4.)
(2) Does not depend on any other World - the package imports no other cortico-world-* package and declares no "features" mechanism; it talks only to the OneBot v11 endpoint. The optional cortico-world-memory bridge had its tool surface removed in 0.6.10 (qq_note dropped); what remains is a pure-data notebook bridge that probes at call time and falls back to a native JSONL backend, so the plugin is fully optional and the World works without it. Per #104 this is documented as an optional enhancement, not a dependency.
(3) Follow-up releases - dozens of published versions (0.0.0-stage through 0.6.19), far past the "at least one follow-up" bar. Security and correctness fixes are documented in CHANGELOG.md, notably since the 0.3.8 review:
  - Reverse WS listener hardening (from #104, still present): wsHost defaults to 127.0.0.1, a per-install random token is persisted to dataDir and shown in the console / startup log, assertReverseListenerIsSafe() refuses to serve an unauthenticated non-loopback listener, and the token is read from the `Authorization: Bearer` header first (OneBot v11 spec) while still accepting ?access_token= / ?token=.
  - Path / file safety: emoji path resolution rejects absolute paths, `..` segments, escapes outside the emoji dir (re-verified via realpath), and requires a regular file; qq_qzone post images are allow-listed to http(s):// and base64:// only, dropping anything else (file:// rejected).
  - @all / @全体成员 / @everyone is no longer parsed into an at-all segment in normal replies; mention-all is gated behind qq_admin authorization.
  - allowPrivateRedirect effective default corrected to false (0.6.15): previously a group member could make the bot private-message an arbitrary QQ.
  - ASR sidecar resolves scripts only inside its own package root (no cross-package scan), preventing execution of another extension's script.
  - qzone external / untrusted text (commenter nickname, original post, recent chat) is moved out of the model prompt into event meta; the judge-voice self-model call reports usage (reportUsage).
  - Mood / affinity / alias were split into a separate bot extension (cortico-bot-qq-persona), so this World no longer carries internal-state tooling.
