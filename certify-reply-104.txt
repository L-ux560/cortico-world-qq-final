All five points were valid; none were disputed. Everything is fixed in cortico-world-qq-final@0.3.8 (verified by unpacking the published tarball, not just the repo). beta is deprecated and points here. Details below, point by point.

## 1. Security - reverse WS listener

- `QQ_DEFAULTS.wsHost` is now `127.0.0.1`, not `0.0.0.0`.
- Reverse connections always authenticate. `world.ensureReverseToken()` generates a 24-byte random token when the config token is empty and persists it to `dataDir/reverse-token.txt`, so it survives restarts; it is shown in the console panel and in the startup log so it can be pasted into the OneBot client.
- `driver.assertReverseListenerIsSafe()` refuses to start when the listen address is not loopback and no token is set, instead of silently serving an unauthenticated port.
- Bonus fix found while testing this: the reverse server only read the token from the query string. OneBot v11 specifies the `Authorization: Bearer <token>` header (the framework's own qq world sends it that way), which is what NapCat/Lagrange actually send, so every connection was rejected. `extractToken()` now reads the header first, still accepts `?access_token=` / `?token=`, and the rejection log no longer echoes the token value.
- `onClientConnect` now closes the previous socket before adopting a new one; previously it overwrote `active` and left the old socket able to send and receive.

## 2. Security - emoji path traversal and file://

- `resolveEmojiFile()` in `src/normalize.ts` rejects absolute paths and any `..` segment, requires the resolved path to stay inside the emoji directory, re-verifies through `realpathSync` so a symlink cannot escape, and requires a regular file. Anything else is dropped silently, matching the previous behaviour for a missing file.
- `qq_qzone_post` images are allow-listed to `http(s)://` and `base64://` only; dropped values are logged. The tool description and README were updated too.

## 3. cortico-world-memory dependency - reframed, not changed

The framework offers no alternative: the `World` contract in `Cortico/src/core/types.ts` only exposes main-loop callbacks (`onTurnEnded` / `onEventsSettled` / `onBatchEnd` / `onIdle`), all invoked on the world itself, with no publish/subscribe channel between worlds. Writing to another world's storage cannot be expressed as an event.

So this is documented as what it is - an optional enhancement, not a dependency. The package does not import `cortico-world-memory` and does not require it: every notebook method probes the bridge at call time and falls back to a native JSONL backend, so all `qq_notebook_*` tools work with the plugin absent. The bridge surface is four pure-data methods (`save`/`list`/`get`/`forget`), it exposes none of the plugin's internals, and the plugin deletes the key on stop so this extension reverts to native immediately. Stated in README under "relationship with cortico-world-memory" and in the `notebook.ts` header comment.

## Breaking change to be aware of

0.3.0 changed the default listen address and made the token mandatory in reverse mode. Migration is either paste the auto-generated token into your OneBot client, or keep `wsHost` at `127.0.0.1`. This is called out in the CHANGELOG.
