Fixed in cortico-world-qq-final@0.3.0 (and mirrored to cortico-world-qq-final-beta@0.2.0-beta.13). Thank you for the review -- all five points were valid and are addressed.

Security

1. Reverse WS no longer listens on all interfaces by default. QQ_DEFAULTS.wsHost is now 127.0.0.1 instead of 0.0.0.0 (src/config.ts). Reaching it from another machine now requires explicitly setting wsHost.

2. Reverse connections always authenticate. Two layers:
   - world.ensureReverseToken() generates a random 24-byte token when the config token is empty and persists it to dataDir/reverse-token.txt, so it survives restarts. It is shown in the startup log and in the console "connection and listening" panel (new getReverseToken method) so it can be pasted into NapCat.
   - driver.assertReverseListenerIsSafe() refuses to start when the listen address is not loopback and no token is set, rather than silently serving an unauthenticated port. Loopback with an empty token only logs a warning.
   Also, onClientConnect now closes the previous connection before adopting a new one, instead of overwriting `active` and leaving the old socket able to send and receive.

3. Emoji path traversal fixed. [emoji:file] previously did join(emojiDir, fname) directly, so ..\..\ reached any file on the machine and it would be sent out as an image. resolveEmojiFile() in src/normalize.ts now rejects absolute paths and any ".." segment, requires the resolved path to stay inside the emoji directory, re-verifies via realpathSync so a symlink cannot escape, and requires a regular file. Anything else is silently dropped, matching the previous behaviour for a missing file.

4. file:// removed from qzone post images. Images come from LLM tool arguments and can be steered by prompt injection in group messages. post() now allow-lists http(s):// and base64:// only and logs the dropped ones. Tool description and README updated.

Dependency (cortico-world-memory)

Reframed rather than changed, because the framework offers no alternative: the World contract in Cortico/src/core/types.ts only exposes main-loop callbacks (onTurnEnded / onEventsSettled / onBatchEnd / onIdle), which are invoked on the world itself, and there is no publish/subscribe channel between worlds. Writing to another world's storage cannot be expressed as an event.

So this is documented as what it is -- an optional enhancement, not a dependency. The package does not import cortico-world-memory and does not require it: every notebook method checks for the bridge at call time and falls back to a native JSONL backend, so all qq_notebook_* tools work with the memory plugin absent. The bridge surface is four pure-data methods (save/list/get/forget), it exposes none of the plugin's internals, and the plugin deletes the key on stop so this extension reverts to native immediately. This is now stated in README under "Relationship with cortico-world-memory" and in the notebook.ts header comment.
